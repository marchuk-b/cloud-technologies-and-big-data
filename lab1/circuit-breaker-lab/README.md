# Circuit Breaker Lab

Навчальний проєкт для дослідження патерна **Circuit Breaker**.

## Мета

- зрозуміти принцип роботи Circuit Breaker;
- змоделювати тимчасову недоступність зовнішнього сервісу;
- перевірити переходи між станами `CLOSED`, `OPEN` і `HALF_OPEN`;
- зменшити кількість невдалих запитів до несправного сервісу.

## Як працює Circuit Breaker

1. **CLOSED** — запити проходять до сервісу, а помилки підраховуються.
2. **OPEN** — після досягнення порога помилок запити блокуються на визначений час.
3. **HALF_OPEN** — виконується тестовий запит:
	- якщо він успішний, контур повертається до `CLOSED`;
	- якщо він невдалий, контур знову переходить до `OPEN`.

## Підготовка

1. Для завантажте репозиторій та перейдіть в папку проекту:

```bash
git clone https://github.com/marchuk-b/cloud-technologies-and-big-data.git
cd lab1/circuit-breaker-lab
```

2. Встановіть залежності:

```bash
npm install
```

## Запуск
Для запуску сервера, скористайтеся командою:
```bash
npm run dev
```

Для дослідження роботи брейкера, паралельно відкрийте термінал та надсилайте запити за допомогою `curl`:
```bash
// Приклад
curl 'http://localhost:5000/?failureThreshold=3&halfOpenMaxCalls=2&openStateDuration=5000&timeoutPerCall=2000&promiseTimeout=1000'
```

Параметри запиту:

- `failureThreshold` — кількість помилок, після якої контур переходить у стан `OPEN`;
- `halfOpenMaxCalls` — максимальна кількість тестових запитів у стані `HALF_OPEN`;
- `openStateDuration` — тривалість перебування у стані `OPEN` у мілісекундах;
- `timeoutPerCall` — максимальний час виконання одного запиту до зовнішнього сервісу у мілісекундах;
- `promiseTimeout` — час очікування завершення проміса у мілісекундах.

## Тести

У файлі `test/circuit-breaker.test.ts` описано набір автоматизованих перевірок для поведінки Circuit Breaker:

- перевірка переходу в стан `OPEN` після досягнення порогу помилок;
- блокування викликів, коли контур перебуває в `OPEN`;
- перехід із `OPEN` в `HALF_OPEN` після завершення таймауту `openStateDuration`;
- повернення в `OPEN` після невдалого тестового запиту в `HALF_OPEN`;
- обробка тайм-ауту, якщо функція виконується довше за `timeoutPerCall`;
- скидання лічильника помилок після успішного запиту;
- перевірка, що повторні помилки після успіху не відкривають контур заново.

Ці тести виконуються через Vitest і дозволяють підтвердити, що реалізація правильно відповідає патерну Circuit Breaker у типових сценаріях роботи.

Запуск тестів:
```bash
npm run test
```
