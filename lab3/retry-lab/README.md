# Retry Lab

Навчальний проєкт для дослідження патерна **Retry**.

## Мета

- зрозуміти принцип роботи retry;
- вивчити, як повторно виконувати операцію після тимчасових помилок;
- перевірити різні стратегії пауз між спробами;
- реалізувати та протестувати власну обгортку для повторних викликів.

## Що таке retry

Retry — це патерн, який повторно виконує операцію, якщо вона завершилася помилкою, поки не досягнуто максимальної кількості спроб або поки помилка не вважається невиправною.

Це корисно для сценаріїв, де можливі короткочасні збої:

- мережеві запити до API;
- тимчасові помилки бази даних;
- збій сервісу під час пікового навантаження;
- повторне виконання асинхронних задач після короткої паузи.

## Як працює реалізація

У цьому проєкті retry реалізовано у класі `Retrier` у файлі `src/retrier.ts`.

Параметри:

- `maxAttempts` — максимальна кількість спроб виконання функції;
- `pauseStrategy` — стратегія затримки між спробами;
- `retryOn` — функція, яка визначає, чи помилка є повторюваною.

Типи пауз між спробами:

- `constant` — однакова затримка між кожною спробою;
- `exponential` — затримка зростає експоненційно: `delay * 2^attempt`;
- `exponentialJitter` — експоненційне збільшення зі випадковим "шумом".

Основні сценарії:

1. `maxAttempts` більше 1, помилка тимчасова  
   Функція повторюється до успіху або до досягнення ліміту.

2. `retryOn` повертає `false`  
   Помилка вважається фатальною, і повтори не виконуються.

3. `pauseStrategy: constant`  
   Між спробами є фіксована затримка.

4. `pauseStrategy: exponential`  
   Затримка збільшується з кожною наступною спробою.

5. `pauseStrategy: exponentialJitter`  
   Пауза збільшується, але додається випадковий фактор для уникнення одночасного повтору кількох клієнтів.

## Підготовка

1. Завантажте репозиторій та перейдіть у папку проєкту:

```bash
git clone https://github.com/marchuk-b/cloud-technologies-and-big-data.git
cd lab3/retry-lab
```

2. Встановіть залежності:

```bash
npm install
```

## Запуск demo

Для запуску демонстраційного прикладу використовуйте:

```bash
npm run dev
```

Ця команда запускає `src/index.ts`, де показані основні сценарії роботи retry:

- успішне виконання з першої спроби;
- повтор після тимчасової помилки;
- досягнення `maxAttempts`;
- невиправна помилка без повторів;
- експоненційна затримка;
- експоненційна затримка з jitter.

## Тести

Проєкт містить автоматизовані тести в `test/retrier.test.ts`.

Вони перевіряють:

- успішне виконання з першої спроби;
- повторні спроби до успіху;
- викидання помилки після досягнення `maxAttempts`;
- відсутність повторів для невиправних помилок;
- коректну роботу фіксованої затримки;
- коректну роботу експоненційної затримки;
- коректну роботу експоненційної затримки з jitter.

Запуск тестів:

```bash
npm run test
```

Також можна перевірити збірку TypeScript:

```bash
npm run build
```
