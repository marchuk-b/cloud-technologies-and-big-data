# Debounce Lab

Навчальний проєкт для дослідження патерна **Debounce**.

## Мета

- зрозуміти принцип роботи debounce;
- вивчити вплив швидких повторних викликів на виконання функції;
- перевірити поведінку режимів `leading` і `trailing`;
- реалізувати та протестувати власну debounce-обгортку.

## Що таке debounce

Debounce — це патерн, який відстрочує виконання функції до моменту, коли протягом заданого інтервалу не надходить нових викликів.

Це корисно для сценаріїв, де одна функція викликається дуже часто:

- введення в текстові поля;
- фільтрація списків;
- події прокрутки або зміни розміру вікна;
- запити до API під час швидкого набору даних.

## Як працює реалізація

У цьому проєкті debounce реалізовано у класі `Debouncer` у файлі `src/debouncer.ts`.

Параметри:

- `delay` — затримка в мілісекундах перед виконанням;
- `leading` — чи викликати функцію одразу при першому зверненні;
- `trailing` — чи викликати функцію після завершення затримки з останніми аргументами.

Основні сценарії:

1. `leading: false`, `trailing: true`  
   Функція виконується один раз після паузи між викликами.

2. `leading: true`, `trailing: false`  
   Функція викликається одразу при першому зверненні, а наступні виклики ігноруються до завершення затримки.

3. `leading: true`, `trailing: true`  
   Спочатку виконується перший виклик, а після затримки — ще один trailing-виклик, якщо були додаткові події.

4. `leading: false`, `trailing: false`  
   Функція не виконується взагалі.

## Підготовка

1. Завантажте репозиторій та перейдіть у папку проєкту:

```bash
git clone https://github.com/marchuk-b/cloud-technologies-and-big-data.git
cd lab2/debounce-lab
```

2. Встановіть залежності:

```bash
npm install
```

## Запуск demo

Для запуску демонстраційного прикладу використовуйте:

```bash
npm run dev
```

Ця команда запускає `src/index.ts`, де показані основні сценарії роботи debounce:

- trailing-only;
- leading-only;
- leading + trailing.

P.S. Для зміни сценарію змінюйте число `testNumber`у файлі `src/index.ts` від 1 до 3.

## Тести

Проєкт містить автоматизовані тести в `test/index.test.ts`.

Вони перевіряють:

- виклик функції після серії швидких звернень;
- immediate виклик при `leading: true`;
- повторне дозволене виконання після завершення затримки;
- комбінацію `leading` і `trailing`;
- відсутність викликів при обох параметрах `false`;
- коректне скасування таймера через `dispose()`.

Запуск тестів:

```bash
npm run test
```

Також можна перевірити збірку TypeScript:

```bash
npm run build
```
